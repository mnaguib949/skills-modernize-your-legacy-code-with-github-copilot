# Account Management System Test Plan

This test plan documents the behavior currently implemented in the COBOL application. It is intended for business validation before and during the migration to Node.js. Unless a case states otherwise, run cases in a fresh application process so the starting balance is reset to `1000.00`.

| Test Case ID | Test Case Description | Pre-conditions | Test Steps | Expected Result | Actual Result | Status (Pass/Fail) | Comments |
|---|---|---|---|---|---|---|---|
| TC-001 | Start the application and display the account menu | Application is compiled and available to run | 1. Start the application. | The application displays the Account Management System menu with options 1. View Balance, 2. Credit Account, 3. Debit Account, and 4. Exit. |  |  |  |
| TC-002 | View the initial account balance | Fresh application process is running; stored balance is `1000.00` | 1. Select `1`. | The application displays `Current balance: 001000.00`. The stored balance is unchanged. |  |  |  |
| TC-003 | View the balance after a prior update | Application is running; a credit or successful debit has already been completed | 1. Select `1`. | The application displays the latest stored balance, reflecting the prior completed update. |  |  |  |
| TC-004 | Credit the account with a whole-number amount | Fresh application process is running; stored balance is `1000.00` | 1. Select `2`. 2. Enter `250`. 3. Select `1`. | The application displays `Amount credited. New balance: 001250.00`. A subsequent balance inquiry displays `001250.00`. |  |  |  |
| TC-005 | Credit the account with a decimal amount | Fresh application process is running; stored balance is `1000.00` | 1. Select `2`. 2. Enter `125.50`. 3. Select `1`. | The application displays a new balance of `001125.50`. A subsequent balance inquiry displays `001125.50`. |  |  |  |
| TC-006 | Credit the account with zero | Fresh application process is running; stored balance is `1000.00` | 1. Select `2`. 2. Enter `0`. 3. Select `1`. | The credit completes and the balance remains `001000.00`. |  |  |  |
| TC-007 | Credit the account with the largest supported amount | Fresh application process is running; stored balance is `1000.00` | 1. Select `2`. 2. Enter `999999.99`. | The application accepts the amount according to the COBOL numeric input definition and applies the credit, or reports the runtime/input behavior without corrupting the balance. Record the observed behavior for migration agreement. |  |  |  |
| TC-008 | Debit an amount less than the available balance | Fresh application process is running; stored balance is `1000.00` | 1. Select `3`. 2. Enter `250`. 3. Select `1`. | The application displays `Amount debited. New balance: 000750.00`. A subsequent balance inquiry displays `000750.00`. |  |  |  |
| TC-009 | Debit the exact available balance | Fresh application process is running; stored balance is `1000.00` | 1. Select `3`. 2. Enter `1000`. 3. Select `1`. | The debit succeeds because the available balance is greater than or equal to the debit amount. The new and subsequent displayed balance is `000000.00`. |  |  |  |
| TC-010 | Reject a debit greater than the available balance | Fresh application process is running; stored balance is `1000.00` | 1. Select `3`. 2. Enter `1000.01`. 3. Select `1`. | The application displays `Insufficient funds for this debit.`. No write occurs and a subsequent balance inquiry still displays `001000.00`. |  |  |  |
| TC-011 | Debit zero | Fresh application process is running; stored balance is `1000.00` | 1. Select `3`. 2. Enter `0`. 3. Select `1`. | The debit passes the funds check, completes, and the balance remains `001000.00`. |  |  |  |
| TC-012 | Attempt a debit after the balance has been reduced to zero | Fresh application process is running | 1. Select `3`; enter `1000`. 2. Select `3`; enter `0.01`. | The first debit succeeds. The second debit is rejected with `Insufficient funds for this debit.` and the balance remains `000000.00`. |  |  |  |
| TC-013 | Perform multiple credits and debits in one session | Fresh application process is running; stored balance is `1000.00` | 1. Credit `500`. 2. Debit `200`. 3. Credit `25.75`. 4. View the balance. | Each successful operation uses the balance produced by the previous operation. The final displayed balance is `001325.75`. |  |  |  |
| TC-014 | Continue using the menu after a completed operation | Application is running | 1. Select `1`, `2`, or `3` and complete the requested interaction. 2. At the next menu, select another valid option. | The application returns to the menu after the operation and processes the next valid selection. |  |  |  |
| TC-015 | Exit the application | Application is running and menu is displayed | 1. Select `4`. | The application displays `Exiting the program. Goodbye!` and terminates. No further menu is displayed. |  |  |  |
| TC-016 | Reject a menu choice below the valid range | Application is running and menu is displayed | 1. Enter `0`. | The application displays `Invalid choice, please select 1-4.` and displays the menu again. The balance is unchanged. |  |  |  |
| TC-017 | Reject a menu choice above the valid range | Application is running and menu is displayed | 1. Enter `5`. | The application displays `Invalid choice, please select 1-4.` and displays the menu again. The balance is unchanged. |  |  |  |
| TC-018 | Reject a non-numeric menu input | Application is running and menu is displayed | 1. Enter a non-numeric value, such as `X`. | The application handles the input according to the COBOL runtime behavior without executing a credit, debit, view, or exit operation. Record the observed behavior for the Node.js migration. |  |  |  |
| TC-019 | Verify a `READ` returns the stored balance | `DataProgram` is available; stored balance has been initialized or written to a known value | 1. Invoke `DataProgram` with operation `READ` and a balance parameter. | The balance parameter is populated with the current `STORAGE-BALANCE`; no value is changed in storage. |  |  |  |
| TC-020 | Verify a `WRITE` replaces the stored balance | `DataProgram` is available | 1. Invoke `DataProgram` with operation `WRITE` and balance `1234.56`. 2. Invoke it with `READ`. | The next `READ` returns `1234.56`. |  |  |  |
| TC-021 | Verify an unsupported data operation has no effect | `DataProgram` is available; stored balance is known, for example `1000.00` | 1. Invoke `DataProgram` with an operation other than `READ` or `WRITE`. 2. Invoke it with `READ`. | No read or write action is performed. The stored balance remains unchanged at `1000.00`. |  |  |  |
| TC-022 | Verify an unsupported operations command has no business effect | `Operations` is available; stored balance is known | 1. Invoke `Operations` with an operation other than `TOTAL `, `CREDIT`, or `DEBIT `. | No balance update or balance display is performed, and control returns to the caller. |  |  |  |
| TC-023 | Verify balance precision and supported numeric range | Application is running; stored balance is `1000.00` | 1. Credit `0.01`. 2. View the balance. 3. Credit `999999.99` in a separate fresh run if needed. | Monetary values are handled with two decimal places. Record whether an overflow or input error occurs when the resulting balance exceeds the COBOL field capacity; this behavior must be explicitly decided for the Node.js implementation. |  |  |  |
